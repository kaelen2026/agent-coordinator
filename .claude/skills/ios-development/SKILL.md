# iOS 功能交付 SOP

硬性约束见 `.claude/rules/swift.md`；视图编写、状态归属、重渲染、导航与并发的具体方法见 `swiftui` skill。**输入**：DoD + 已冻结的 API 契约。**输出**：五态齐全、编译与测试全绿的 iOS 实现。

## 步骤 1：从契约建模型（向前兼容是硬约束）

- 为每个用到的 endpoint 写 Codable 模型；枚举加 `unknown` case + 自定义 `init(from:)` 兜底，未知字段自然忽略——满足 `swift.md` 的向前兼容要求。
- 用契约样本数据写解码测试：正常样本、多余字段样本、未知枚举值样本三种都过。
- ✅ 检查点：给模型喂"契约之外多一个字段 + 一个未知枚举值"的 JSON，解码成功且降级正确。

## 步骤 2：实现网络层

- 请求集中在网络层，按 async/await 暴露接口；网络失败/超时/4xx/5xx 区分为不同错误类型。
- 依赖（URLSession、token 提供者）经初始化器注入，便于测试替换。
- 后端未就绪时用契约样本数据 mock；联调验收必须打真实 API。

## 步骤 3：实现 ViewModel（状态显式建模）

- 业务逻辑放 `@Observable` ViewModel：View 只读状态、发意图（数据流规则见 `swiftui` skill 步骤 2）。
- 界面状态显式建模为枚举（如 `enum ViewState { loading, empty, loaded(Data), error(AppError), unauthenticated, offline }`），不用散落的布尔标志。
- "服务端给了意外值"建模为一种展示状态（隐藏该项/占位），不散落 if-else。

## 步骤 4：实现 View 与导航

按 `swiftui` skill 的步骤 1-4 执行（视图拆分、状态归属、重渲染控制、类型化导航）。

## 步骤 5：覆盖五态

对照步骤 3 的状态枚举逐一实现 UI：加载中、空数据、错误（可重试的给重试入口）、未登录、离线。缺一视为未完成。

涉及契约的新功能配后端开关（feature flag），线上出问题服务端可关闭。

## 步骤 6：测试与交付前验证

- ViewModel/UseCase 单元测试（依赖注入假实现）；网络层用契约样本测解码与错误分支；新业务逻辑按 `.claude/rules/tdd.md` 测试先行。
- 依次执行并贴输出：编译 → `xcodebuild test`。模拟器上手动走通关键路径。

## 完成检查

- [ ] 解码测试含多余字段与未知枚举样本
- [ ] 界面状态显式建模，五态齐全
- [ ] ViewModel 依赖全部经注入、有单元测试
- [ ] 编译与测试全绿（有输出为证）；待联调项已标注

## 最佳实践（推荐，非强制；偏离时说明理由）

- 无障碍与系统适配从第一版做：支持 Dynamic Type（用系统字体样式不写死字号）、关键控件有 accessibility label、深色模式用语义颜色。
- 文案从第一天进 String Catalog，哪怕暂不翻译——后补国际化要动每个 View。
- 弱网是常态不是边界：用 Network Link Conditioner 在高延迟/丢包下手动走一遍关键路径，请求给用户可感知的进行中状态。
- 接入崩溃上报 + MetricKit（启动时间、卡顿、电量），发版后盯首日指标。
- 启动路径保持轻：第三方 SDK 延迟初始化，主线程启动阶段不做磁盘/网络 IO。
- 本地缓存明确策略（内存 + 磁盘、过期时间、登出清空），不散落各处各自为政；敏感数据不进磁盘缓存。
