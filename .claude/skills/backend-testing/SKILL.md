# 后端测试 SOP

规范底线见 `.claude/rules/testing.md`。**输入**：待测行为或待验收的 DoD。**输出**：可重复、能失败、分层合理的测试。

## 步骤 1：为行为选测试层级

| 待测内容 | 层级 | 依赖 |
|---|---|---|
| service 层业务规则、纯函数 | 单元 | 无 IO |
| repository 查询、约束、迁移；队列生产/消费 | 集成 | 本地容器起真库/真队列，不 mock（mock 的 SQL 永远是对的） |
| API endpoint | 集成 | HTTP client 打真实路由 |
| 关键用户旅程 | 端到端 | 完整启动的服务，只留冒烟路径 |

金字塔形：单元最多，端到端最少（超过 10 个先质疑该不该下沉）。本表是全项目测试分层的唯一定义（`rules/testing.md` 引用于此）。

本地真库/真队列用仓库基建：`pnpm infra:up` 起 PostgreSQL + Redis（compose.yaml，`--wait` 阻塞到健康）；QA 模拟依赖故障用 `docker compose stop postgres`（测完 `start` 恢复）。

## 步骤 2：准备测试数据

- 工厂函数造数据：`make_task(status="pending", **overrides)`，默认值合法、按需覆盖；不用共享巨型 fixture。
- 隔离策略二选一全项目统一：每测试事务回滚（快），或随机前缀/独立 schema（可并行）。

## 步骤 3：写测试（Arrange-Act-Assert）

- 三段分离：准备 → 执行一个行为 → 断言。一个测试只测一个行为。
- 断言查数据库最终状态，不只断言返回值——副作用才是后端的主产品。
- 测试名描述行为：`test_expired_task_is_requeued`，不是 `test_process_2`。
- 边界穷举：空、零、最大值、非法枚举。
- ✅ 检查点：临时注释掉被测实现的关键行，测试应变红（能失败才可信）。

## 步骤 4：驯服不确定性

- **时间**：注入时钟，固定时钟验证过期/超时逻辑，不 sleep 等真实时间。
- **随机/UUID**：注入生成器，给定种子。
- **并发**：用 barrier 让两个操作真正同时进临界区（如同时领同一任务），断言只有一个成功——不靠碰运气压测。
- **重试**：注入"失败 N 次再成功"的假依赖，断言重试次数与退避。

## 步骤 5：mock 纪律

- 只 mock 进程外边界：第三方 HTTP API、邮件/短信、支付。
- mock 响应用真实抓包样本，不凭想象编造。
- 每个被 mock 的外部依赖，另备少量打真实沙箱的契约测试（可单独跑，不进主流水线）。

## 步骤 6：QA 验收（qa agent 执行）

1. 把 DoD 逐条转成可执行命令（curl / CLI / 测试脚本）；
2. 逐条执行并记录证据（命令 + 输出摘录）；拿不到证据的标"未验证"，不默认通过；
3. 异常路径至少覆盖：非法参数、缺认证、越权访问、依赖宕机（真实停容器）；
4. 回归：全量测试套件 + 至少一个与改动相邻的老功能手工路径。

## 完成检查

- [ ] 每个测试删实现关键行会失败（抽查）
- [ ] 无 sleep、无顺序依赖、可并行、连跑 3 遍结果一致
- [ ] 幂等/并发/重试逻辑有针对性测试
- [ ] 集成测试用真实 DB/队列容器

## 最佳实践（推荐，非强制；偏离时说明理由）

- 给测试速度定预算并守住：单测套件 < 1 分钟、集成套件 < 5 分钟——TDD 循环的可行性取决于反馈速度，套件变慢是技术债，专项治理。
- 前后端契约用消费者驱动的契约测试（或至少共享 schema 校验）钉住，防止"后端改了字段前端运行时才炸"。
- 关键路径做基准测试并记录基线，性能回归和功能回归一样挡在合并前。
- flaky 测试立即隔离（单独标记、不阻塞主流水线）并建修复 issue，比"重跑一次就绿"的文化便宜得多。
- 覆盖率当雷达不当 KPI：盯"新增代码的未覆盖分支"找漏网行为，不追求总数字——为覆盖率写的测试通常是恒真断言。
- 种子数据只放全环境共享的不变量（角色、枚举表），业务数据一律工厂函数按需造，两者混用会让测试互相污染。
- 测试代码与生产代码同等对待：重复的 Arrange 抽 helper、命名讲究、评审时一起看。
