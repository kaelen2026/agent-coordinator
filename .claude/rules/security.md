# 安全规则

以下为硬性红线，违反任何一条是 reviewer 的 BLOCKER。

## 输入与注入

- 一切外部输入（HTTP 参数、header、队列消息体、Webhook 回调、文件内容）视为不可信：先校验类型/长度/取值范围，再使用。
- SQL 一律参数化查询，禁止字符串拼接 SQL（含 ORM 的 raw query）。
- 禁止把外部输入拼进 shell 命令、文件路径（防路径穿越）、eval/反序列化调用。
- 反序列化只用安全格式（JSON）；禁止 pickle/marshal 等可执行反序列化处理外部数据。

## 认证与授权

- 每个非公开 endpoint 必须显式声明认证要求；"忘了加"不是豁免理由，默认拒绝。
- 授权检查在 service 层做资源归属校验（这条数据是否属于当前主体），不能只在路由层查登录态——防越权（IDOR）。
- 内部服务间调用同样需要凭证，不因"在内网"而裸奔。

## 密钥与敏感数据

- 密钥、token、密码只能来自环境变量或密钥管理服务；禁止出现在代码、配置文件、日志、错误信息、测试夹具中。
- 日志中禁止输出：完整 token、密码、身份证件号、完整手机号/邮箱（需要时脱敏）。
- 密码存储只用自适应哈希（bcrypt/argon2），禁止 MD5/SHA 系列裸哈希。
- API 返回体默认白名单字段，禁止直接序列化整个数据库模型对象。

## 错误处理与信息泄露

- 对外错误响应不含堆栈、SQL、内部路径、依赖版本号；详细信息只进服务端日志。
- 认证失败的响应不区分"用户不存在"和"密码错误"。

## 依赖与资源

- 新增第三方依赖需说明用途；不引入无人维护（>2 年未更新）的库处理安全敏感逻辑。
- 所有对外 endpoint 有限流；所有出站调用有超时——没有超时的网络调用视为 bug。
- 上传/接收内容必须限制大小与类型。
