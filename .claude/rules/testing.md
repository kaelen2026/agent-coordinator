# 测试规则

具体技法见 `backend-testing` skill；本文件定义"必须做到什么"。

## 必须有测试的情形

- 每个新的对外行为（API endpoint、队列消费者、定时任务）至少一个正向 + 一个异常路径测试。
- 每个修复的 bug 先写复现测试（红），再修（绿）——防止回归。
- 涉及并发/幂等/重试的逻辑必须有针对性测试，不能只测单次调用。

## 测试质量底线

- 断言必须能失败：禁止 `assert True`、断言恒成立的字段、或只断言"没抛异常"。
- 测试之间相互独立：不依赖执行顺序，不共享可变全局状态；每个测试自建自清数据。
- 不 mock 被测对象本身；mock 只用于隔离外部边界（第三方 API、时钟、随机数）。数据库和队列优先用真实实例（本地容器）而非 mock。
- 测试名描述行为而非实现：`test_expired_task_is_requeued`，不是 `test_process_2`。

## 分层策略

| 层 | 测什么 | 依赖 |
|---|---|---|
| 单元 | service 层业务规则、纯函数 | 无 IO，毫秒级 |
| 集成 | repository + 真实 DB、队列生产/消费 | 本地容器 |
| 端到端 | 关键用户旅程（少量，只覆盖冒烟路径） | 完整启动的服务 |

金字塔形：单元最多，端到端最少。端到端测试超过 10 个时先质疑是不是该下沉。

## 执行要求

- 提交前全量测试必须绿；不允许 skip 掉失败测试来换绿。
- 测试必须可重复：连续跑 3 遍结果一致；发现 flaky 测试当 bug 修，不重试掩盖。
- 声称"测试通过"时必须附运行输出，口头声称无效。
